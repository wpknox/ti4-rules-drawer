# CLAUDE.md

TI4 Rules Drawer: a browser extension (Chrome, plus a Safari wrapper) that injects a slide-out, searchable Twilight Imperium 4 rules reference into [TI Assistant](https://ti-assistant.com). The intended setup is one laptop driving TI Assistant on a TV, so the UI is keyboard-first, large text, and dark.

Rules content is bundled from [tirules-search](https://github.com/wpknox/tirules-search) (the owner's fork of dangothemango/tirules, which carries Dane's official rulings as `<span class="ruling">`). Content is GPL-3.0, so this repo is GPL-3.0.

## Layout

```
extension/            The extension. Plain JS/CSS, no dependencies, no build step.
  manifest.json       MV3; content script only on ti-assistant.com (+ www., dev.)
  content.js          Everything in the drawer: UI, search, highlighting, history, keys
  drawer.css          Styles, loaded into the drawer's shadow root
  background.js       Toolbar button + Alt/Option+R command -> message to content script
  rules.json          GENERATED by scripts/build-rules.mjs. Never edit by hand.
  icons/              Rendered from dev/icon.svg
scripts/
  build-rules.mjs     tirules-search PHP pages -> extension/rules.json
  build-safari.sh     Builds/signs/installs the Safari app to ~/Applications
safari/               Xcode project from safari-web-extension-converter.
                      References ../../../extension/* by relative path, so it doesn't copy them.
dev/harness.html      Loads content.js in a fake page with chrome.* stubs, for quick testing
```

## Commands

```bash
node scripts/build-rules.mjs [path/to/tirules-search]   # or set TIRULES_DIR; default ../tirules-search
sh scripts/build-safari.sh                               # Safari: rebuild after ANY extension/ change
python3 -m http.server 8765                              # then open /dev/harness.html and press /
```

Chrome: `chrome://extensions` → Load unpacked → `extension/`; after edits click reload on the card, then reload the TI Assistant tab.

There are no automated tests. Verify in `dev/harness.html` (Playwright works well against it), then in a real browser.

## How content.js works (invariants to keep)

- **Shadow DOM isolation.** The host `<div id="ti-rules-drawer">` is appended to `document.documentElement` rather than `body`, so React re-renders of the body can't remove it. Styles go in the shadow root only.
- **One text function for indexing and highlighting.** `textOf(root)` concatenates text nodes and skips `<style>` nodes. Every rules page has a `<style>` holding its LRR number, e.g. `'77.'`. Search snippets and on-page highlights both use it, which is why "click snippet N" lands on match N. Any change to how text is collected must apply to both.
- **`normChars` must stay one-for-one.** It swaps curly quotes and dashes for straight ones without changing string length, so offsets in normalized text match offsets in the DOM text.
- **Matches can span elements** (e.g. `the <b>Move Ships</b> substep`). `highlight()` splits marks across text nodes and groups them per match.
- **History** is an in-memory stack of `{type: "home" | "results" | "page", q?, occ?, scroll?}`. Recent searches, recent pages, font size and width are saved in `storage.local`.
- **Extension API alias:** `const ext = globalThis.browser ?? globalThis.chrome` (Safari vs Chrome). Use `ext.*`, never `chrome.*` directly.
- **Keyboard:** Alt/Option shortcuts match `e.code` (`KeyR`, `KeyH`, `ArrowLeft`…), not `e.key`, because on a Mac Option+R produces `®`. `altShortcut()` runs from both the window listener and the shadow listener so they work wherever focus is. `toggle()` is debounced because Alt+R can arrive both as a Chrome command and as a keydown.
- Rules load lazily: `rules.json` is fetched through `web_accessible_resources` on first open, then indexed in the browser (about 150 pages, searches take a few ms).

## Gotchas we've hit

- `String.prototype.replaceAll` with a regex **without the `g` flag throws**. A SonarQube-driven change did this in `esc()` and silently broke every render (stuck on "Loading rules…"). Use string arguments: `.replaceAll("<", "&lt;")`.
- Pressing Enter in a `<form>` fires a synthetic click on the submit button. The shadow-root click handler only treats real `<a>` elements as links.
- Render errors go through `showError()`, which uses `textContent` so it still works if a helper like `esc()` is broken. Keep render paths inside its try/catch.
- `rules.json` changes on every build (`builtAt`). If the rules didn't change, `git checkout -- extension/rules.json` rather than committing timestamp noise.
- **Safari bundles a copy** of `extension/` at build time, so it won't see edits until `build-safari.sh` runs.
- `build-safari.sh` **moves** the built app out of `safari/build/`. A copy left behind registers a duplicate extension with Safari.
- The Xcode project's macOS deployment target must be ≥ 12.0. The converter generated 10.14, and current Xcode refuses that for signed builds.

## Privacy rules for this public repo

- **Apple Team ID** lives only in `safari/team-id` (gitignored). `build-safari.sh` passes it on the `xcodebuild` command line. Never write `DEVELOPMENT_TEAM` into `project.pbxproj`. If Xcode's GUI adds it, remove it before committing.
- **Xcode file headers** add `// Created by <full name>`. Strip them from any new Swift files.
- `HANDOFF.md` (session history, local machine details) is gitignored on purpose.
- Before pushing, grep the staged diff for personal names, `/Users/`, and Team IDs.

## Conventions

- Vanilla JS, no dependencies, no bundler. Match the existing style: section banners (`// ── Name ───`), short "why" comments, `$()` for shadow-root queries.
- Keep the drawer keyboard-drivable. New actions get a shortcut plus a tooltip that shows it, built with the `ALT` label constant (⌥ on Mac).
- Credit upstream rules authors (dangothemango, BradleyΣ) wherever rules content is shown.
